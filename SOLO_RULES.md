## 1. Идея

Одна змейка, без соперника. По незахваченной части поля летают **шарики** и отскакивают от твоей земли и стен. Выходишь из дома — оставляешь след. Шарик коснулся следа — теряешь жизнь. Замкнул контур — закрашиваются все отрезанные области, **в которых нет шариков**. Захватил 75% — следующий уровень, шариков больше.

---

## 2. Поле и старт уровня

- Поле **20×20** (`BOARD_SIZE` — параметр режима, у Duel остаётся 15).
- Своя земля в начале уровня — **рамка**: все клетки с `x = 0`, `x = 19`, `y = 0` или `y = 19` (76 клеток).
- **Внутреннее поле** — 18×18 = **324** клетки. Прогресс считается только по ним.
- Старт змейки в начале уровня: `(9, 19)`, direction `RIGHT` — вдоль нижней кромки, по своей земле.

### 2.1 Точка возрождения (после потери жизни)
- Кандидаты — 4 клетки: середины сторон рамки `(9,19)` RIGHT, `(0,9)` DOWN, `(10,0)` LEFT, `(19,10)` UP (направление — вдоль рамки, против часовой стрелки на экране, т.к. ось y направлена вниз).
- Выбирается кандидат, у которого **минимальное расстояние до ближайшего шарика** (по Чебышёву) максимально. При равенстве — первый в указанном порядке.
- Очередь нажатий игрока очищается при потере жизни (в game loop), чтобы старое нажатие не вывело змейку с рамки сразу после отсчёта.
- Шарики: на уровне `N` их `N + 1` на Normal (уровень 1 — 2 шарика) и `N` на Easy (уровень 1 — 1 шарик), см. раздел 13. Позиции — случайные клетки внутреннего поля (seeded rng), не ближе 6 клеток (по Чебышёву) к старту змейки и не в одной клетке друг с другом. Направления — случайные диагональные `(±1, ±1)`.

## 3. Модель данных

```
SoloState {
  board: Cell[20][20]            // Cell { territory: NONE | P1, trail: NONE | P1 } — те же слои, что в Duel
  player: Player                 // как в Duel: head, direction, trail[], alive
  balls: { pos: {x,y}, vel: {dx,dy} }[]   // dx, dy ∈ {-1, +1}
  level: number                  // с 1
  lives: number                  // старт 3, максимум 5
  score: number
  progress: number               // захваченные клетки внутреннего поля / 324, 0..1
  round: number                  // тики с начала уровня
  status: PLAYING | LIFE_LOST | LEVEL_COMPLETE | GAME_OVER
  seed: number                   // для детерминизма шариков
  difficulty: 'easy' | 'normal'  // задаётся при создании, не меняется до конца партии
}
```

Движок Solo — отдельный модуль (`src/engine/solo/`), который **переиспользует** из движка Duel: допустимые ходы, обновление следа и алгоритм захвата. Duel-код и его тесты не меняются, кроме обобщения захвата (раздел 6).

---

## 4. Движение шариков

Шарики живут только на клетках, которые **не являются землёй**. След для шарика — не препятствие: попадание в след = удар (раздел 5).

Каждый шарик делает один диагональный шаг **на тиках, когда шарики ходят** (Normal — каждый тик; Easy — каждый второй тик, см. раздел 13). Отскок, для шарика в `(x, y)` со скоростью `(dx, dy)`:
1. Если клетка `(x + dx, y)` — земля или за полем → `dx = -dx`.
2. Если клетка `(x, y + dy)` — земля или за полем → `dy = -dy`.
3. Если ни 1, ни 2 не сработали, но клетка `(x + dx, y + dy)` — земля (угол) → `dx = -dx`, `dy = -dy`.
4. Если целевая клетка `(x + dx, y + dy)` после разворотов свободна от земли — шарик переходит в неё. Иначе остаётся на месте в этом тике (зажат в тупике).

Шарики не сталкиваются друг с другом и могут находиться в одной клетке.

---

## 5. Разрешение тика (порядок строго фиксирован)

1. **Валидация хода** змейки (как в Duel).
2. **Движение змейки.** Голова сдвигается на клетку.
3. **Свой след.** Голова встала на клетку своего следа → потеря жизни (`SELF_TRAIL`).
4. **Голова в шарик.** Голова (вне своей земли) встала на клетку, где сейчас шарик → потеря жизни (`BALL_HIT`).
5. **Захват.** Если голова на своей земле и след не пуст → захват (раздел 6). Шарики на этом шаге ещё не двигались.
6. **Обновление следа.** Голова вне земли → клетка головы добавляется в след.
7. **Движение шариков** (раздел 4) — по доске после захвата, только если на этом тике шарики ходят (`round % BALL_STEP_EVERY == 0`).
8. **Шарик в след.** (проверяется на каждом тике, даже если шарики не двигались) Любой шарик на клетке следа (включая клетку головы) → потеря жизни (`BALL_HIT`).
9. **Уровень.** `progress ≥ 0.75` → `LEVEL_COMPLETE`.
10. `round += 1`.

Шаги 4 + 8 вместе покрывают «перекрёстный» случай, когда голова и шарик проходят друг сквозь друга: старая клетка головы — это клетка следа.

Если на шаге 3/4/8 потеряна жизнь — дальнейшие шаги тика не выполняются.

---

## 6. Захват

Тот же алгоритм, что в GAME_RULES.md раздел 7, обобщённый:

1. **Препятствия** = своя земля ∪ свой след.
2. Остальные клетки → компоненты связности (4-соседство).
3. **Исключаются все компоненты, в которых есть хотя бы один шарик.**
4. **Захват** = клетки следа + все клетки неисключённых компонент.

Если шарики есть во всех компонентах — захватывается только след.

Обобщение для движка: `computeCapture(board, player, excludedCells: Pos[])` — компонента исключается, если содержит любую из `excludedCells`. Duel передаёт `[голова врага]` и сохраняет своё правило «самой большой компоненты», если голова врага на земле игрока. Solo передаёт позиции всех шариков. Все тесты Duel должны пройти без изменений.

## 7. Жизни, уровни, очки

**Потеря жизни:**
- `lives -= 1`, событие `LIFE_LOST { reason, at }`.
- След удаляется (клетки становятся пустыми), захваченная земля остаётся.
- Змейка возвращается в точку возрождения (2.1). Шарики остаются где были.
- На тике потери жизни `round` не увеличивается.
- Короткая вспышка места удара — мигает **рамка** клетки (шарик и след в клетке остаются видны), затем отсчёт 3-2-1 и продолжение.
- `lives == 0` → `GAME_OVER`.

**Уровень пройден:**
- `score += 100 × level` плюс `50 × level` за каждый полный процент сверх 75.
- `lives = min(lives + 1, 5)`.
- Новый уровень: доска снова рамка, шариков на один больше, отсчёт 3-2-1.

**Очки за захват:** `score += (захваченные клетки внутреннего поля) × level`. Большой захват одним контуром выгоднее — это и есть риск.

Лимита по времени в Solo нет.

## 8. Контракт

```ts
createSoloState(opts: { seed: number; difficulty?: 'easy' | 'normal'; level?: number; lives?: number; score?: number }): SoloState   // difficulty по умолчанию 'normal'
getLegalMoves(state, 'P1'): Direction[]                   // тот же, что в Duel
resolveSoloTick(state: SoloState, move: Direction): { state: SoloState; events: SoloEvent[] }
continueSolo(state: SoloState): SoloState   // LIFE_LOST → PLAYING (возрождение по 2.1) или LEVEL_COMPLETE → новый уровень (PLAYING)

type SoloEvent =
  | { type: 'MOVED'; from: Pos; to: Pos }
  | { type: 'TRAIL_STARTED' }
  | { type: 'CAPTURED'; cells: Pos[]; points: number }
  | { type: 'BALLS_MOVED'; balls: { from: Pos; to: Pos }[] }
  | { type: 'LIFE_LOST'; reason: 'SELF_TRAIL' | 'BALL_HIT'; at: Pos; livesLeft: number }
  | { type: 'LEVEL_COMPLETE'; level: number; bonus: number }
  | { type: 'GAME_OVER'; level: number; score: number }
```

Чистые функции, вход не мутируется, шарики детерминированы от `seed`.

---

## 9. Инварианты Solo

- **S1.** Шарик никогда не стоит на земле.
- **S2.** Слой `trail` доски совпадает с `player.trail` (как I1 в Duel).
- **S3.** `0 ≤ progress ≤ 1`; внутри уровня прогресс не убывает.
- **S4.** `1 ≤ lives ≤ 5` пока `PLAYING`.
- **S5.** Число шариков = `level + 1` на Normal и `level` на Easy.
- **S6.** Рамка всегда остаётся землёй.

## 10. Тест-кейсы

- **ST01** Старт уровня 1: рамка 76 клеток, 2 шарика во внутреннем поле, не ближе 6 к старту, змейка `(9,19)` RIGHT.
- **ST02** Отскок от стены-земли по горизонтали, по вертикали, в углу (правила 4.1–4.3).
- **ST03** Шарик зажат в тупике — остаётся на месте.
- **ST04** Шарик входит в клетку следа → `LIFE_LOST BALL_HIT`, след удалён, змейка на старте, земля сохранена.
- **ST05** Голова въезжает в клетку с шариком → `BALL_HIT`.
- **ST06** Перекрёстный проход головы и шарика → `BALL_HIT` (через шаг 8).
- **ST07** Свой след → `SELF_TRAIL`.
- **ST08** Захват: область без шариков закрашивается, область с шариком — нет.
- **ST09** Захват, когда шарики во всех областях → захвачен только след.
- **ST10** Прогресс ≥ 75% → `LEVEL_COMPLETE`, бонус по формуле, +1 жизнь (не выше 5), новый уровень с 3 шариками.
- **ST11** Последняя жизнь → `GAME_OVER`.
- **ST12** Детерминизм: один `seed` + одни ходы → одинаковая партия.
- **ST14** Возрождение: шарик у нижней кромки → змейка возрождается в самой дальней от шариков середине стороны; при равенстве — первая по порядку.
- **ST15** Easy: уровень 1 — 1 шарик; шарики двигаются только на чётных тиках (`round` 0, 2, 4…); на нечётном тике шарик стоит, но удар по следу (шаг 8) всё равно проверяется.
- **ST16** Easy, уровень 2 — 2 шарика; Normal, уровень 2 — 3 шарика.
- **ST13** Все тесты Duel проходят после обобщения `computeCapture`.
- **Stress:** 2000 партий случайного бота-змейки с `assertSoloInvariants` после каждого тика.

## 11. UI

- Меню: выбор режима **DUEL / SOLO**. Difficulty (EASY / NORMAL) и Speed — для обоих режимов; сложность запоминается отдельно для каждого режима.
- HUD Solo: `LV 1` · прогресс `42% / 75%` · жизни (квадратики) · очки.
- Шарик: квадрат/круг **#FF00FF** (яркая мадженту) ~70% клетки — отличается и от земли, и от следа.
- HOW TO PLAY: отдельный экран для Solo, 4 пункта со схемами.
- Статистика: `ts_solo` — `gamesPlayed`, `bestScore`, `bestLevel` **отдельно для easy и normal**; в `ts_games` записи с `mode: "solo"`, `level`, `score`, `reason`, `rematch`.
- Название «Xonix» и другие чужие названия не используются.

## 12. Риски для плейтеста

1. Поле 20×20 на 375px — клетка ~17px: проверить, что шарики и след хорошо видны.
2. Змейка в Solo тоже не останавливается (автоход) — на своей земле она ездит по рамке; проверить, не раздражает ли. Кандидат: в Solo на своей земле змейка стоит, пока не нажата клавиша.
3. Скорость шариков = скорость змейки. Если слишком сложно — шарики ходят через тик на уровнях 1–2.

## 13. Сложность (Easy / Normal)

| Параметр | Easy | Normal |
|---|---|---|
| Шариков на уровне `N` | `N` | `N + 1` |
| Шарики ходят | каждый **второй** тик (`BALL_STEP_EVERY = 2`) | каждый тик (`BALL_STEP_EVERY = 1`) |
| Цель уровня | 75% | 75% |
| Жизни | старт 3, +1 за уровень, максимум 5 | так же |
| Очки | по той же формуле | — |

- Сложность выбирается в меню перед партией и не меняется до её конца.
- **Рекорды раздельные**: `bestScore` и `bestLevel` для Easy и Normal хранятся отдельно, экран GAME OVER сравнивает с рекордом своей сложности («NEW BEST!»). Существующие рекорды при миграции относятся к Normal.
- По умолчанию для нового игрока — **Easy**.
- Рендеринг: на Easy шарик интерполируется на 2 тика (плавное движение без остановок через тик).
- Параметры — константы в одном конфиге (`SOLO_DIFFICULTY`), чтобы подстроить после плейтеста без изменения кода движка.
