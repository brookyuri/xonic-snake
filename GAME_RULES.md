## 1. Система координат и обозначения

- Поле **15×15**, координаты `(x, y)`.
- `x` растёт вправо (0…14), `y` растёт **вниз** (0…14). `(0,0)` — левый верхний угол.
- Направления: `UP = (0,-1)`, `DOWN = (0,+1)`, `LEFT = (-1,0)`, `RIGHT = (+1,0)`.

Игроки:

| id | Цвет | Кто | Старт |
|----|------|-----|-------|
| `P1` | BLUE | человек | низ поля |
| `P2` | RED | бот | верх поля |

Обозначения в сетках:

```
.  пустая клетка
B  территория BLUE        R  территория RED
b  след BLUE              r  след RED
1  голова BLUE            2  голова RED
```

Под головой всегда есть «настоящее» состояние клетки (территория, след или пусто) — оно указывается в тексте примера.

---

## 2. Модель данных

> **Отличие от PRD:** в PRD клетка имеет одно из 5 состояний. Этого недостаточно — BLUE может идти по территории RED, и клетка одновременно «территория RED» и «след BLUE». Поэтому у клетки **два независимых слоя**.

```
Cell {
  territory: NONE | P1 | P2
  trail:     NONE | P1 | P2
}

Player {
  id: P1 | P2
  head: {x, y}
  direction: UP | DOWN | LEFT | RIGHT   // направление последнего хода
  trail: {x, y}[]                        // упорядоченный, от выхода из дома до головы
  alive: boolean
}

GameState {
  board: Cell[15][15]
  players: { P1, P2 }
  round: number                          // 0 до первого хода
  maxRounds: number                      // лимит матча, задаётся при создании (раздел 5.3)
  status: PLAYING | FINISHED
  result?: { winner: P1 | P2 | DRAW, reason: Reason }
}

Reason = TRAIL_CUT | SELF_TRAIL | ENGULFED | HEAD_ON | MUTUAL | NO_TERRITORY | ROUND_LIMIT
```

Доска индексируется как `board[y][x]` (строка, затем столбец).

Размер территории вычисляется из `board`, отдельно не хранится (или хранится как кэш, пересчитываемый после каждого раунда).

## 4. Базовые понятия

- **Дома** — голова стоит на клетке своей территории.
- **Вне дома** — любая другая клетка: пустая или территория противника.
- **След** — клетки, которые голова посетила вне дома с момента последнего выхода, **включая текущую клетку головы**.
- Территория игрока не обязана быть связной.

## 5. Ходы

### 5.1 Реальное время: тики
Игра идёт сама. Раунд = **тик** фиксированной длительности. На каждом тике оба игрока делают по одному шагу **одновременно** (раздел 6).

- Змейка движется в текущем направлении без участия игрока. Игрок только **меняет направление**.
- Стоять на месте нельзя — если игрок ничего не нажал, ход = текущее направление (оно всегда допустимо, кроме упора в стену — см. ниже).
- **Упор в стену:** если текущее направление ведёт в стену и игрок не повернул, выбирается первый допустимый ход по часовой стрелке от текущего направления (UP → RIGHT → DOWN → LEFT). Это касается и человека, и бота. Смерти от стены нет.
- Бот выбирает ход **только по состоянию на начало тика** и не знает хода человека.
- Engine не знает о времени: он получает два хода и разыгрывает раунд. Таймер, очередь нажатий и паузу реализует UI-слой (game loop).

### 5.1.1 Очередь нажатий (человек)
- Нажатия складываются в очередь **максимум из 2** направлений. Каждый тик забирает одно.
- Нажатие игнорируется, если оно равно последнему направлению в очереди (или текущему, если очередь пуста) либо противоположно ему.
- Лишние нажатия сверх 2 игнорируются.
- **Нажатие в стену.** Если на тике направление из очереди ведёт в стену, оно отбрасывается, и ход выбирается по обычному правилу: текущее направление, а при упоре — по часовой стрелке (5.1). Следующий элемент очереди остаётся на следующий тик.
- Пример: змейка идёт UP, за один тик нажаты RIGHT, DOWN → тик N: RIGHT, тик N+1: DOWN (разворот через 2 тика, без потери нажатия).

### 5.1.2 Старт и пауза
- Матч начинается с отсчёта 3-2-1, поле уже видно.
- Пауза: кнопка в HUD, клавиша Space/P, автопауза при сворачивании вкладки (`visibilitychange`). Возобновление — снова с отсчёта 3-2-1.

### 5.2 Допустимые ходы
Направление недопустимо, если:
1. ведёт за пределы поля (**стена блокирует**, это не смерть);
2. противоположно текущему `direction` (разворот на 180°).

Оба правила действуют всегда — и дома, и вне дома.

Стоять на месте нельзя. У игрока **всегда есть хотя бы один допустимый ход** (даже в углу: из двух направлений внутрь поля максимум одно является разворотом).

Engine при получении недопустимого хода бросает ошибку (это баг вызывающего кода, а не игровое событие). Game loop обязан гарантировать, что в engine попадают только допустимые ходы (очередь 5.1.1 + правило упора в стену).

### 5.3 Скорость и длительность матча
| Скорость | Тик | `maxRounds` (2 минуты) |
|---|---|---|
| Slow | 400 мс | 300 |
| Normal | 280 мс | 429 |
| Fast | 180 мс | 667 |

- `maxRounds = ceil(120000 / tickMs)`, задаётся в `createInitialState({ maxRounds })`. По умолчанию — 100 (для тестов и бенчмарка).
- HUD показывает оставшееся время `(maxRounds − round) × tickMs`, в формате `1:47`, не больше `2:00`.
- Скорость и длительность — константы в одном месте, легко меняются после плейтеста.

## 6. Разрешение раунда (порядок строго фиксирован)

Вход: `state`, `moveP1`, `moveP2`. Обозначим `S0` — состояние на начало раунда (не мутировать).

**Шаг 1. Валидация.** Оба хода допустимы по 5.2.

**Шаг 2. Движение.** Обе головы сдвигаются на одну клетку. Обновить `direction`.

**Шаг 3. Лоб в лоб.** Срабатывает, если:
- (a) обе головы оказались в одной клетке, **или**
- (b) головы поменялись местами (`newHeadP1 == oldHeadP2` и `newHeadP2 == oldHeadP1`).

Итог (игра заканчивается в любом случае, `reason = HEAD_ON`):
1. Если **ровно один** игрок стоит на клетке своей территории (по `S0`) — он побеждает.
2. Иначе побеждает игрок с большей территорией (по `S0`).
3. Равенство — `DRAW`.

Если лоб в лоб произошёл — шаги 4–7 не выполняются.

**Шаг 4. Удары по следам.** Используются следы из `S0`.
- Новая голова игрока стоит на клетке **следа противника** → противник погибает (`TRAIL_CUT`).
- Новая голова игрока стоит на клетке **своего следа** → игрок погибает (`SELF_TRAIL`).
- Погибли оба → `DRAW` (`MUTUAL`). Погиб один → второй побеждает.

Если кто-то погиб — игра заканчивается, шаги 5–7 не выполняются (захваты этого раунда не засчитываются).

> Следствие: **«сначала удар»**. Если в этом раунде я замыкаю контур, а противник встаёт на клетку моего следа — я погибаю, захвата нет. Мой след был открыт на начало раунда.

**Шаг 5. Захваты.** Для каждого игрока, чья новая голова стоит на своей территории **и** чей след не пуст — вычислить захват по разделу 7. Оба захвата вычисляются от одного и того же состояния (после шага 2, до применения любого захвата), затем применяются вместе:
- Клетки, захваченные **обоими** игроками одновременно, остаются у прежнего владельца.
- Остальные захваченные клетки получают `territory = захватчик` **и `trail = NONE`** (слой следа на захваченных клетках всегда очищается, иначе на безопасной клетке останется «призрачный» след).
- След захватчика очищается (его клетки уже вошли в захват).
- Если в захваченную область попала хотя бы одна клетка **следа противника** → противник погибает (`ENGULFED`). Погибли оба → `DRAW` (`MUTUAL`).
- Клетки, захваченные обоими, **не** вызывают `ENGULFED` — противник в этом же раунде сам замкнул контур.
- След погибшего от `ENGULFED` снимается целиком.
- Событие `CAPTURED` содержит только реально применённые клетки (без пересечений).

**Шаг 6. Обновление следов.** Для каждого живого игрока: если голова стоит **не** на своей территории — добавить клетку головы в след (`board.trail = игрок`, push в `player.trail`).

Это же правило покрывает случай, когда противник захватил территорию, на которой стоит голова: клетка перестала быть «домом» — начинается след.

**Шаг 7. Конец раунда.**
- Если у живого игрока территория стала **0** → он проигрывает (`NO_TERRITORY`). Оба → `DRAW`.
- `round += 1`.
- Если `round == maxRounds` и игра не закончена → побеждает игрок с большей территорией (`ROUND_LIMIT`, в UI — «Time's up»), равенство → `DRAW`. Открытые следы в подсчёт не входят.

## 7. Алгоритм захвата

Вызывается для игрока `A` против противника `E`, когда `A` вернулся домой со следом.

1. **Препятствия** = клетки территории `A` ∪ клетки следа `A` (включая клетку, где след только что замкнулся).
2. Все остальные клетки поля (пустые, территория `E`, след `E`) разбить на **компоненты связности** (4-соседство, край поля — стена).
3. Определить **исключённую компоненту**:
   - та, в которой стоит голова `E`;
   - если голова `E` не лежит ни в одной компоненте (стоит на территории `A`) — исключается **самая большая** компонента; при равенстве размеров исключаются все самые большие.
4. **Захват** = клетки следа `A` + все клетки всех неисключённых компонент.

Свойства, которые должны проверяться тестами:
- Области, прижатые к краю поля, захватываются (в отличие от flood fill от границы из PRD).
- Территория `E` внутри захвата переходит к `A`.
- Компонента с головой `E` никогда не захватывается, поэтому голову противника «съесть» нельзя — но его след можно (→ `ENGULFED`).
- Если след просто прошёл вдоль своей территории и ничего не отрезал — захватываются только клетки следа.

Сложность: O(225) на захват, BFS. Никаких оптимизаций в MVP не нужно.

## 8. Подсчёт и отображение

- `territorySize(P)` = число клеток с `territory == P`.
- Процент = `round(territorySize / 225 * 100)`.
- Проценты BLUE и RED **не обязаны давать 100%** — пустые клетки не принадлежат никому. UI показывает `BLUE 12%   RED 9%`, а не нормализует.

## 9. Контракт engine (для UI и бота)

Все функции чистые, без React, без мутации входа.

```ts
createInitialState(opts?: { maxRounds?: number }): GameState
getLegalMoves(state: GameState, player: PlayerId): Direction[]
resolveRound(state: GameState, moveP1: Direction, moveP2: Direction): {
  state: GameState
  events: GameEvent[]
}

type GameEvent =
  | { type: 'MOVED'; player: PlayerId; from: Pos; to: Pos }
  | { type: 'TRAIL_STARTED'; player: PlayerId }
  | { type: 'CAPTURED'; player: PlayerId; cells: Pos[]; stolenFromEnemy: number }
  | { type: 'DIED'; player: PlayerId; reason: Reason; at: Pos }   // at — клетка столкновения / поглощения
  | { type: 'GAME_OVER'; winner: PlayerId | 'DRAW'; reason: Reason; detail?: HeadOnDetail }

type HeadOnDetail = 'DEFENDER_HOME' | 'BIGGER_TERRITORY' | 'EQUAL'   // только при reason = HEAD_ON
```

Порядок событий в конце игры: сначала `DIED` для каждого погибшего, затем ровно одно `GAME_OVER`. При ничьей `HEAD_ON` или `MUTUAL` — `DIED` для обоих игроков. При победе по `HEAD_ON` — `DIED` для проигравшего. При `ROUND_LIMIT` событий `DIED` нет.

`events` нужны UI для анимаций (вспышка захвата, смерть) — UI не должен сам вычислять разницу между состояниями.

Бот видит ровно то же, что и человек: полный `GameState`. Никакой скрытой информации в игре нет.

## 10. Что сознательно НЕ входит в правила

## 11. Примеры = тест-кейсы

В фрагментах указан диапазон координат. Всё, что вне фрагмента, — как в стартовой позиции, если не сказано иное.

### T01 — Выход из дома и начало следа
Старт. BLUE: `UP` → `(7,11)` (своя территория, следа нет). Следующий раунд: `UP` → `(7,10)` — вне дома.
Ожидание: `player.trail = [(7,10)]`, `board[7][10].trail = P1`, событие `TRAIL_STARTED`.

### T02 — Разворот запрещён
BLUE с `direction = UP`. `getLegalMoves` не содержит `DOWN`. `resolveRound(state, DOWN, …)` бросает ошибку.

### T03 — Стена блокирует
BLUE на `(3,14)` с `direction = LEFT`. `getLegalMoves` = `[UP, LEFT]` (`DOWN` — стена, `RIGHT` — разворот).

### T04 — Простой захват
Фрагмент `x = 5..10`, `y = 8..13`. Маршрут BLUE от `(7,12)`: `UP, UP, UP, RIGHT, RIGHT, DOWN, DOWN`. Голова на `(9,11)` (след).

```
     x 5678910
y 8    ......
  9    ..bbb.
 10    ..b.b.
 11    .BBB1.
 12    .BBB..
 13    .BBB..
```

Ход `LEFT` → `(8,11)`, своя территория → захват.

```
     x 5678910
y 8    ......
  9    ..BBB.
 10    ..BBB.
 11    .BB1B.
 12    .BBB..
 13    .BBB..
```

Ожидание: захвачено 7 клеток (6 следа + `(8,10)`), территория BLUE = 16, след пуст, событие `CAPTURED`.

### T05 — Захват кармана у стены
Фрагмент `x = 0..6`, `y = 10..14`. Территория BLUE включает блок `x = 5..9`, `y = 12..14`. BLUE вышел с `(5,12)` и прошёл: `LEFT ×3, DOWN ×2, LEFT, UP ×3, RIGHT ×4`. Голова на `(5,11)`.

```
     x 0123456
y10    .......
 11    .bbbb1.
 12    .bbbbBB
 13    .bb..BB
 14    .bb..BB
```

Ход `DOWN` → `(5,12)`, своя территория → захват. Карман `(3,13) (4,13) (3,14) (4,14)` касается нижней стены.
Ожидание: карман захвачен вместе со следом. Колонка `x = 0` не захвачена (она связана с остальным полем, где голова RED).

```
     x 0123456
y10    .......
 11    .BBBBB.
 12    .BBBB1B
 13    .BBBBBB
 14    .BBBBBB
```

### T06 — Перерезание следа
Фрагмент `x = 3..9`, `y = 6..7`. BLUE вне дома, след `(4,6)…(7,6)`, голова `(8,6)`. Голова RED на `(5,7)`.

```
     x 3456789
y 6    .bbbb1.
  7    ..2....
```

RED: `UP` → `(5,6)` — след BLUE на начало раунда.
Ожидание: BLUE погибает, `winner = P2`, `reason = TRAIL_CUT`. Ход BLUE в этом раунде значения не имеет (если только BLUE сам не встал на след RED — см. T08).

### T07 — «Сначала удар»
BLUE в одном ходе от замыкания. В этом же раунде RED встаёт на клетку следа BLUE.
Ожидание: BLUE погибает, захват **не** применяется, территория BLUE не меняется.

### T08 — Взаимный разрез
В одном раунде BLUE встаёт на след RED, а RED — на след BLUE.
Ожидание: `DRAW`, `reason = MUTUAL`.

### T09 — Свой след
BLUE вне дома, след образует «крючок». BLUE делает ход на свою старую клетку следа (не предыдущую — туда нельзя по развороту).
Ожидание: BLUE погибает, `reason = SELF_TRAIL`.

### T10 — Лоб в лоб, одна клетка, защитник дома
BLUE на `(5,5)` → `RIGHT`, RED на `(7,5)` → `LEFT`. Обе головы в `(6,5)`. `(6,5)` — территория RED.
Ожидание: `winner = P2`, `reason = HEAD_ON`.

### T11 — Лоб в лоб, обмен местами
BLUE на `(5,5)` → `RIGHT`, RED на `(6,5)` → `LEFT`. Ни одна из клеток назначения не является своей территорией для прибывшего. Территории: BLUE 20, RED 15.
Ожидание: `winner = P1`, `reason = HEAD_ON`.

### T12 — Лоб в лоб, равенство
Как T11, но территории равны → `DRAW`.

### T13 — Захват территории противника
BLUE замыкает контур, внутри которого есть клетки территории RED (голова RED снаружи).
Ожидание: эти клетки становятся территорией BLUE; территория RED уменьшается на столько же; `stolenFromEnemy > 0`.

### T14 — Компонента с головой противника не захватывается
BLUE замыкает контур так, что голова RED оказывается внутри.
Ожидание: эта область не захвачена; захвачены только остальные отрезанные компоненты и след BLUE.

### T15 — Голова противника на моей территории
RED стоит на территории BLUE. BLUE замыкает контур, который отрезает две компоненты — маленькую и большую.
Ожидание: захвачена только маленькая (исключается самая большая).

### T16 — Поглощение следа противника
RED вне дома, часть его следа лежит внутри области, которую захватывает BLUE.
Ожидание: RED погибает, `reason = ENGULFED`, `winner = P1`.

### T17 — Одновременные захваты с пересечением
Оба замыкают контур в одном раунде, их захваты пересекаются.
Ожидание: пересекающиеся клетки остаются у прежнего владельца, остальное применяется.

### T18 — Клетка под головой противника не захватывается
RED стоит дома, рядом BLUE замыкает контур. Ожидание: клетка под головой RED при захвате никогда не меняет владельца (она всегда в исключённой компоненте). Инвариант проверять на всех тестах захвата.

### T19 — Территория стала 0
Территория RED полностью захвачена, RED жив и вне дома.
Ожидание: RED проигрывает, `reason = NO_TERRITORY`.

### T20 — Лимит раундов
После раунда 100 оба живы. BLUE 40 клеток, RED 35 → `winner = P1`, `reason = ROUND_LIMIT`. Открытый след RED длиной 10 в подсчёт не входит.

### T21 — Лимит раундов, ничья
Как T20, но территории равны → `DRAW`.

### T22 — След вдоль своей границы
BLUE выходит на одну клетку и сразу возвращается на соседнюю клетку своей территории, ничего не отрезав.
Ожидание: захвачена только клетка следа.

### T23 — Проценты
Территория BLUE 27 клеток → UI показывает `12%`. Сумма процентов меньше 100 — это корректно.

### T24 — Чистота функций
`resolveRound` не мутирует входной `state` (проверка через deep freeze или сравнение копии).

## 12. Риски для плейтеста (не менять до первых матчей)

1. **Карман с врагом внутри.** Если голова RED в маленьком кармане, BLUE по правилу 7.3 забирает остальную карту. На практике RED почти всегда погибает раньше через `ENGULFED` (его след пересекает большую область). Если в плейтесте всплывут абсурдные захваты — перейти на правило «захватывается всё, кроме компоненты с головой врага **и** самой большой».
2. **Одновременность + полная информация.** Проверить, появляется ли блеф, или все играют «гарантированно безопасно».
3. **Длительность и скорость.** 2 минуты и три скорости — стартовые значения. Смотреть в метриках: сколько партий доходит до «Time's up».
4. **Старт 3×3.** Если первые 10 раундов скучные — попробовать 5×3.

## 13. Инварианты состояния

Должны выполняться после **каждого** `resolveRound`. В тестах проверяются функцией `assertInvariants(state)`.

- **I1.** Слой `trail` на доске точно совпадает со списками `player.trail`: клетка имеет `trail = P` ⇔ она есть в `P.trail`. Никаких «призрачных» следов.
- **I2.** Клетка следа игрока никогда не является его собственной территорией.
- **I3.** Следы двух игроков не пересекаются (пока игра идёт).
- **I4.** Пока `status = PLAYING`: голова живого игрока стоит либо на своей территории (и тогда его след пуст), либо на последней клетке своего следа. После окончания игры не проверяется (шаг 6 не выполнялся).
- **I5.** Соседние клетки `player.trail` — соседи по 4-связности.
- **I6.** `territorySize(P1) + territorySize(P2) ≤ 225`.
- **I7.** Пока `status = PLAYING`, у каждого игрока территория > 0 и `round < maxRounds`.
- **I8.** Игра всегда заканчивается не позже раунда `maxRounds`.
